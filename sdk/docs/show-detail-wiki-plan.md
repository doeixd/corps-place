# Show Detail Wiki Plan — rich, editable per-show pages

Status: **Planning (rev 2).** No code yet. This doc is the contract for the build.
Rev 2 folds in the design review: persistence pinned to the `/data` volume (C-1),
row-level overlay instead of block-level adoption (H-1), write-through cache
invalidation (H-2), SQLite WAL/concurrency (H-3), SSR read-only render (M-3),
lazy page creation (M-4), and the validated one-show-per-corps-per-season fact (M-1).

## 1. Goal

Turn every corps show (this season and every season back) from "title + a few
repertoire lines" into a deep, living page: full staff, repertoire with
composers/arrangers and movement breakdown, listen-to links, show & uniform
announcement links, uniform colors/photos/about, prop photos/explanations,
symbolism, an open-ended concept essay, and a media wall (covers, clips,
Instagram/TikTok/YouTube/X). Anyone signed in can edit, Notion-style, with
pre-proposed sections and media drop zones that invite contribution. A
right-sidebar panel shows the full, revertible edit history.

### 1.1 Non-goals (for now)
- Real-time multiplayer co-editing (Yjs/CRDT). Last-write-wins per overlay row +
  an optimistic-concurrency token + a divergence flag is enough; revisit only if
  collisions become real.
- Editing the scraped pipeline through the UI. Scrapers stay code-driven.
- Public anonymous editing. Login required (better-auth). See §6.
- Moderation queue / approval workflow. History + revert is the v1 backstop;
  formal moderation is a later milestone (M9).
- Full visual rich-text diffing in the history sidebar. v1 ships a text diff of
  `plain` + structured op summaries (see §12 M-2).

## 2. Goals behind the goal (taste / principles)

- **Scraped facts and human prose never blend at rest.** Two physically separate
  stores, merged at read time. This keeps provenance honest ("from DCI" vs "by
  @user") and lets the scraper keep improving without re-typing.
- **The bot proposes, the human disposes — at the smallest possible grain.** A
  scraped value renders live until a human overrides *that specific value*; the
  override wins thereafter, everything untouched keeps getting scraper
  improvements. Drift on overridden values is surfaced, never auto-merged.
- **Contributions are irreplaceable.** Scraped data is re-derivable; a fan's
  essay and uploaded photos are not. The contributions store lives on the durable
  volume and gets backup/care the generated stores don't.
- **The editor is a small part of the page.** Pinned structured blocks are typed
  React forms, not rich-text. Only the free-form section is a rich editor. Don't
  let editor choice metastasize into the whole design.
- **Empty is an invitation.** Unfilled sections render as inviting drop
  zones/prompts, not blank space or "N/A".
- **Fail closed on durability.** If the write path can't reach the durable volume,
  refuse writes rather than persist to an ephemeral container FS (see §3.2).

## 3. Architecture: the overlay model

```
  Scraped (nightly, read-only, wholesale-swapped)   Contributions (durable, user-writable)
  ┌──────────────────────────────┐                  ┌────────────────────────────────────────┐
  │ corps_shows                  │                   │ show_pages          (1 per corps+season) │
  │ corps_show_repertoire        │  ─── merge ────▶  │ show_block_overrides(per-row overlay)    │
  │ corps_show_designers         │    at read time   │ show_blocks         (authored + freeform)│
  │ corps_show_movements         │                   │ show_revisions      (append-only)        │
  │ corps_show_media             │                   │ show_media          (R2 uploads)         │
  └──────────────────────────────┘                  │ auth_* tables       (better-auth)        │
              │                                      └────────────────────────────────────────┘
              └────────────────► Show detail page ◄──────────────┘
```

- Scraped tables live in `dci-relational.db` / the emitted read-model (unchanged;
  see `sdk/src/extraDomain.ts:160` `CorpsShowSchema`, `sdk/src/relational.ts`
  show tables, `app/lib/server-fns/hybrid.ts:119` `getShowInfoForSeason`).
- **New: `contributions.db`** — a libsql/SQLite file that is the source of truth
  for everything users write and is **never regenerated by the emit cycle.**
- Render rule, per overridable value: **`displayed = override ?? scraped`.**

### 3.1 Persistence (C-1): the durable volume is the source of truth
The production container is rebuilt on every deploy (`Dockerfile`: single stage,
nothing writable baked in). The read-model and `media-cache.db` survive only
because they sit on a **Coolify persistent volume mounted at `/data`**
(`docker-entrypoint.sh` pulls the read-model into `/data` on boot). Therefore:

- `contributions.db` path = **`/data/contributions.db`**, via env
  `CONTRIBUTIONS_DB_URL` (default `file:/data/contributions.db`). **Never** a path
  inside the image/container FS.
- The **persistent volume is the durable store** (the thing we must not lose). R2
  is **disaster recovery** for volume loss, not the primary safety net.
- RPO is therefore "volume loss" (rare), bounded for DR by the backup interval
  (§10). This is strictly better than the rev-1 "backup interval is the only RPO".

### 3.2 Fail-closed mount guard (C-1)
On boot the entrypoint asserts `/data` is a real mount (e.g. a sentinel file the
volume must contain, or `mountpoint -q /data`). If absent:
- Reads still serve (scraped read-model is best-effort anyway).
- **All write server-fns fail closed** with a clear error; we never write
  contributions to an ephemeral FS that a redeploy will discard. Surfaced in the
  health/log output so a misconfigured deploy is loud, not silent.

### 3.3 Why on-box SQLite (not managed Postgres)
Decision (operator preference): operational symmetry with the existing SQLite
stores, zero new managed-service dependency, and the durable volume + R2 DR meet
the irreplaceability bar. Revisit only if write concurrency outgrows one box
(§3.5 / H-3 bound this).

## 4. Field-level ownership (the real data-model decision)

Every piece of show data is exactly one of three classes:

| Class | Examples | Owner | Behavior |
|---|---|---|---|
| **Scraped-only** | scores, premiere date, venue, official announcement URLs | scraper | Read-only on page; never authored. |
| **Seedable** | repertoire works, staff/designer roles, movements, official media | scraper → then human, **per row** | Each scraped row renders live until a human overrides *that row*; the override wins thereafter, every other row stays live. |
| **Authored-only** | uniform colors/about, props, symbolism, free-form essay, fan media, social links | human | No scraped counterpart; lives entirely in contributions. |

### 4.1 Row-level overlay (H-1) — the corrected adoption model
Rev 1 snapshotted a whole seedable *block* on first edit, which froze every row
in it from future scraper improvements. Rev 2 overrides at **row grain**:

- A seedable section is a set of scraped rows keyed by **natural identity** (§5).
  Each renders live from scrape **unless** a `show_block_overrides` row exists for
  that exact `(page_id, pinned_key, natural_key)`.
- Editing one work writes **one** override row + a `source_hash` of the scraped
  value it was based on — for *that work only*. Every other work stays live and
  keeps getting scraper improvements.
- A human can also **add** rows the scraper never had (override row with no
  scraped counterpart) and **hide** a scraped row (a tombstone override) — both at
  row grain.
- `scrape_diverged` is **per override row**, so the "DCI changed this" banner is
  precise ("this piece changed", not "something in repertoire changed").
- Authored-only pinned blocks (uniform, props, links, symbolism) and free-form
  blocks have no scraped rows, so they use the single-`content_json` model
  (`show_blocks`), not the overlay table.

Rejected alternatives: (a) block-level adopt-on-edit — rots the whole block
(rev-1 flaw). (b) live-from-scrape-until-explicit-detach — extra "detach" UI
concept and surprising "my edit vanished" behavior. Row-level overlay is the
wiki-correct, lowest-surprise choice.

## 5. Keys & identity (the subtle part)

- **Do not anchor contributions to scraped `show_id`** — it can re-key on
  re-ingest / source-URL change. Anchor to the stable business key
  **`(corps_key, season)`**, which is also how users navigate.
- **Validated (M-1):** the scraped data is currently 777 shows across 777 distinct
  `(corps_key, season)` pairs — exactly one show per corps per season, zero
  collisions. So `show_pages` carries `UNIQUE (corps_key, season)`. The scraped
  `corps_shows` PK is `show_id` (no such uniqueness), so the reconciler (§9)
  **logs loudly** if it ever sees two scraped shows share a `(corps_key, season)`,
  turning a future invariant break into an alert instead of silent corruption.
- `show_pages.show_id` is a *soft* pointer, re-resolved nightly by the reconciler.
- **Natural identity** for seedable rows (the override key), chosen to be stable
  across re-keys:
  - repertoire → `normalize(work_title)` + ordinal within the show
  - staff/designers → `normalize(role)` + `normalize(name)`
  - movements → `ordinal`
  - media → normalized URL / asset hash
  `normalize()` = lowercase, trim, collapse whitespace, strip punctuation. Stored
  alongside the override so a scraper text tweak that doesn't change the
  normalized key keeps the override attached.
- `corps_key` and `season` validated against the scraped directory on page create
  (no orphan pages for corps/seasons that don't exist).

## 6. Auth, permissions & validation

### 6.1 Auth (better-auth)
- **Three methods:** Google (social), **passkey** (WebAuthn, better-auth passkey
  plugin), and **magic link** (better-auth magicLink plugin). Passwordless across
  the board — no password storage/reset surface to maintain. Tables live in
  `contributions.db` (`/data`).
- `app/lib/auth.ts` (server config: googleProvider + passkey() + magicLink()) +
  `/api/auth/*` handler route + a session helper usable inside server fns.
- **Magic link needs a transactional email sender** (the one new external
  dependency). Pick a provider (e.g. Resend/Postmark/SES) and put the API key in
  env; the `sendMagicLink` callback delivers the token. Domain + SPF/DKIM setup is
  a deploy task. Without it, magic-link sign-in silently fails — so wire a
  startup check that warns when the email key is absent (Google + passkey still
  work). Tracked under M2.
- **Passkey** requires the site's `rpID`/origin configured to the production
  domain; localhost works for dev. WebAuthn needs HTTPS (the Cloudflare tunnel /
  Coolify TLS already provides it).
- **Reads public, writes gated.** All write server-fns require a session; the
  editor UI only mounts for authenticated users. This fills the gap the codebase
  already flags ("there is no admin auth yet" — `app/lib/server-fns/corps-colors.ts:7`).
- **Migration boundary (L-2):** better-auth owns and migrates its own `auth_*`
  tables via its adapter/CLI; our migrations never touch them. Co-located in the
  same file for operational simplicity; split to a separate SQLite file only if
  session-write churn shows up as `SQLITE_BUSY` (§8.1).

### 6.2 Permission model — open wiki + capability roles
The original vision is "wiki where anyone can edit." We hold that line:
**editing is the default capability, not a privilege.** Roles grant *extra*
(mostly destructive/structural) powers that protect the commons — they do **not**
gate the act of contributing. Rejected: pure page-ownership/claiming (contradicts
open editing, stalls coverage, breeds disputes) and admin-gated CRUD (a CMS
bottleneck across 777+ shows, not a wiki).

| Capability | anon | user | trusted | moderator | admin |
|---|---|---|---|---|---|
| Read pages | ✅ | ✅ | ✅ | ✅ | ✅ |
| Edit blocks / override rows | — | ✅ | ✅ | ✅ | ✅ |
| Upload media | — | ✅ (rate-limited) | ✅ | ✅ | ✅ |
| Revert a revision (own + others) | — | ✅ | ✅ | ✅ | ✅ |
| Edit a **locked** page | — | — | ✅ | ✅ | ✅ |
| Lock / unlock a page | — | — | — | ✅ | ✅ |
| Hide a revision / media | — | — | — | ✅ | ✅ |
| Mark page orphaned / merge | — | — | — | ✅ | ✅ |
| Grant/revoke roles, ban users | — | — | — | — | ✅ |
| Delete a page (rare) | — | — | — | — | ✅ |

- **trusted** = auto-granted after N accepted edits or hand-promoted; mainly "no
  rate limit" + "edit through a lock." A spam-resistance tier, not a gatekeeper.
- **moderator/admin** are the moderation backstop (M9) — capabilities reserved now,
  built later.

### 6.3 Soft stewardship (not hard claiming)
A user may **steward** a show — a *non-exclusive* flag (`show_stewards`) granting
notifications ("someone edited Blue Devils 2024", "DCI diverged on a row you
wrote"), contributor surfacing, and revert-weighting in moderation heuristics. It
confers **zero exclusive control**; many users can steward one page. This
satisfies the "this is my corps's page" pull while keeping the wiki open.

### 6.4 Page locking (abuse valve)
`show_pages.lock_level` (`none` | `trusted` | `mod`) lets a moderator freeze a page
during a vandalism spike without deleting anything. Edits below the lock level are
rejected at the server fn (same fail-closed treatment as the volume guard, I-7),
explained in the UI.

### 6.5 The `authorize()` chokepoint
A single server-side `authorize(session, action, page)` helper is called at the top
of **every** write server-fn — the *only* place permission is decided (generalizes
how `corps-colors.ts` gates on `isDev` today). UI affordances (hiding buttons) are
cosmetic; the server is the gate. Every revision records `author_id` (I-9) **and**
`actor_role` frozen at write time, so a later role change never rewrites history's
meaning.

### 6.6 Validation — Valibot for contribution input, Effect Schema for the scraped domain
CORRECTION (implemented): `@formisch/react` is **Valibot-coupled** — it introspects
Valibot object schemas to build its field paths, so it does NOT accept Effect
Schema. So **contribution input uses Valibot** (`app/lib/contrib/schemas.ts`): the
SAME Valibot schema drives the Formisch form (client) AND the server re-parse
(`v.parse`) — one source of truth per concern, no duplication. **Effect Schema
stays** for the scraped/read domain (`extraDomain.ts`, the read-model) and for
server-fn transport envelopes.

Four layers, defense in depth:

```
1. Form (client)      Formisch + Valibot     inline UX, disable-submit, field errors
2. Transport (server) SAME Valibot schema    re-parse (v.parse) in the write server-fn (never trust client)
3. Domain invariants (server)                concurrency token, allowlists, pinned_key whitelist, hex-normalize, sanitize
4. DB constraints                            UNIQUE / NOT NULL / CHECK as the last backstop
```

- **Layer 1/2:** each authored block/override has one Effect Schema (e.g.
  `UniformInputSchema`, `RepertoireRowSchema`). Formisch binds it on the client;
  the write fn re-parses with `SchemaParser.decodeUnknownEffect` (the pattern
  already used in `staffAiExtract.ts`) — client validation is UX only, the server
  parse is authoritative.
- **Layer 3** (handler logic Schema can't express): `pinned_key` ∈ allowed set;
  **optimistic concurrency** — incoming `expectedUpdatedAt` must equal stored
  `updated_at` else 409 refresh-and-retry (§12); **embed/link host allowlist**
  (reuse the SSRF allowlist); media refs must belong to this page.
- **Layer 4:** `UNIQUE` / `NOT NULL` / `CHECK (pinned_key IN (...))` backstop.

**Free-form editor content is XSS-critical** (rich content rendered to other
users). Effect Schema validates the *envelope* `{format, version, doc, plain}` and
bounds size, but **cannot** vouch for the rich content's safety:
- Store and render the **structured node tree**, never arbitrary HTML. The
  read-only SSR renderer (M-3) walks the editor JSON through an **allowlist of node
  types** (heading/paragraph/quote/image/embed/callout) + known attributes only;
  anything else is dropped. This is why "structured `doc`, not HTML" matters for
  security, not just diffing.
- Server-side, verify `plain` is the flattened text of `doc` (cheap) so
  search/diff can't be poisoned independently of the rendered content.

## 7. Content model: pinned blocks + free-form

### 7.1 Pinned structured blocks (uniform across all shows, undeletable)
Identified by `pinned_key`. Always present, render even when empty (as drop
zones). Each has a typed Effect Schema (validated on write, §6.6) bound to a Formisch form.
Proposed set and storage:

| pinned_key | shape | class | storage |
|---|---|---|---|
| `repertoire` | ordered works {workTitle, composer, arranger, movementRef, listenLinks[], notes} | seedable | per-row overlay |
| `staff` | roles {role, name, personRef?} | seedable | per-row overlay |
| `movements` | ordered {ordinal, title, repRefs, notes} | seedable | per-row overlay |
| `media` | gallery {assets[]: cover/clip/photo + social embeds} | seedable + authored | per-row overlay |
| `uniform` | {colors[], description, announcementUrl, images[]} | authored | single `content_json` |
| `props` | {items[]: {name, description, images[]}} | authored | single `content_json` |
| `links` | {showAnnouncement, uniformAnnouncement, social[]: {platform, url}} | authored | single `content_json` |
| `symbolism` | short structured notes | authored | single `content_json` |

These are **React forms**, not editor content: color picker, role list, image
drop zone. Undeletable by construction (no delete affordance; absent overrides
fall back to scraped/empty-prompt).

### 7.2 Free-form section (the rich editor)
One ordered list of rich blocks (heading/paragraph/quote/image/embed/callout),
seeded with helper placeholder blocks ("Describe the concept…", "Drop the uniform
reveal here"). `@dnd-kit` (already in repo) for reorder. This is the **only** place
a rich-text editor runs.

### 7.3 Editor: storage-agnostic contract (decide via spike)
Operator prefers **Lexical**; trial Lexical / TipTap / Editor.js behind one
`<FreeFormEditor value onChange>` interface (M-spike). Storage is editor-agnostic
from day one so a swap never strands content:

```
content_json (free-form block) = {
  format: "lexical" | "tiptap" | "editorjs",
  version: 1,
  doc: <editor-native JSON>,       // editor-native, opaque to the rest of the app
  plain: "<flattened text>"        // search, previews, diff fallback (always populated)
}
```

Rendering, revision diffs, and search lean on `format` + `plain`. **SSR
requirement (M-3):** the server renders a read-only view from `doc`/`plain`; the
editor instance is a **client-only island** mounted only when signed in and the
user clicks "edit". Logged-out + crawler traffic never loads editor JS. This is an
acceptance gate of M-spike — each candidate must support read-only SSR render.

Spike evaluation axes: read-only SSR render, media drop-zone feel, `/`-insert UX,
JSON cleanliness for diffing, React 19 friction, bundle size. Recommendation lean:
Lexical (React-native, clean state, first-class custom nodes, strong a11y); TipTap
safe fallback; Editor.js only if its flat-array diffability outweighs its weak
React glue.

## 8. Schema (contributions.db)

```sql
show_pages (
  page_id      TEXT PRIMARY KEY,         -- stable, owned here
  corps_key    TEXT NOT NULL,
  season       TEXT NOT NULL,
  show_id      TEXT,                      -- soft pointer, re-resolved nightly
  status       TEXT NOT NULL DEFAULT 'active', -- active | orphaned
  lock_level   TEXT NOT NULL DEFAULT 'none',   -- none | trusted | mod (§6.4)
  created_at   TEXT NOT NULL,
  updated_at   TEXT NOT NULL,
  UNIQUE (corps_key, season)
)

-- Non-exclusive stewardship (§6.3) — notifications/surfacing, no exclusive control.
show_stewards (
  page_id    TEXT NOT NULL,
  user_id    TEXT NOT NULL,
  created_at TEXT NOT NULL,
  PRIMARY KEY (page_id, user_id)
)

-- Per-row overlay for SEEDABLE pinned sections (repertoire/staff/movements/media).
show_block_overrides (
  override_id   TEXT PRIMARY KEY,
  page_id       TEXT NOT NULL,
  pinned_key    TEXT NOT NULL,           -- which seedable section
  natural_key   TEXT NOT NULL,           -- stable id of the scraped row (§5)
  state         TEXT NOT NULL,           -- 'edited' | 'added' | 'hidden'(tombstone)
  content_json  TEXT,                    -- the authored row value (null for 'hidden')
  source_hash   TEXT,                    -- hash of scraped row at override time (null for 'added')
  scrape_diverged INTEGER NOT NULL DEFAULT 0,
  position      INTEGER,                 -- for 'added' rows / explicit ordering
  updated_at    TEXT NOT NULL,
  updated_by    TEXT NOT NULL,
  UNIQUE (page_id, pinned_key, natural_key)
)

-- AUTHORED-only pinned blocks + free-form blocks (no scraped counterpart).
show_blocks (
  block_id      TEXT PRIMARY KEY,
  page_id       TEXT NOT NULL,
  kind          TEXT NOT NULL,           -- 'pinned' | 'freeform'
  pinned_key    TEXT,                    -- non-null iff kind='pinned' (uniform/props/links/symbolism)
  position      INTEGER NOT NULL,        -- freeform ordering
  content_json  TEXT NOT NULL,
  updated_at    TEXT NOT NULL,
  updated_by    TEXT NOT NULL,
  UNIQUE (page_id, pinned_key)           -- one row per authored pinned key
)

show_revisions (                          -- append-only, never UPDATE/DELETE
  revision_id  TEXT PRIMARY KEY,
  page_id      TEXT NOT NULL,
  target_kind  TEXT NOT NULL,            -- 'override' | 'block' | 'page'
  target_id    TEXT,                     -- override_id / block_id / null
  author_id    TEXT NOT NULL,
  created_at   TEXT NOT NULL,
  op           TEXT NOT NULL,            -- create|edit|revert|reorder|add|hide|restore
  actor_role   TEXT NOT NULL,            -- role frozen at write time (§6.5)
  before_json  TEXT,
  after_json   TEXT,
  summary      TEXT
)

show_media (
  media_id     TEXT PRIMARY KEY,
  page_id      TEXT NOT NULL,
  block_id     TEXT,                      -- or override_id; nullable
  r2_key       TEXT NOT NULL,
  kind         TEXT NOT NULL,             -- image|cover|clip|embed
  width        INTEGER, height INTEGER,
  alt          TEXT, attribution TEXT,
  uploaded_by  TEXT NOT NULL,
  uploaded_at  TEXT NOT NULL
)
-- plus better-auth's own tables (auth_user, auth_session, auth_account, ...).
-- auth_user is extended with: role TEXT NOT NULL DEFAULT 'user'
--   (user | trusted | moderator | admin — §6.2).
```

Indexes: `show_block_overrides(page_id, pinned_key)`, `show_blocks(page_id)`,
`show_revisions(page_id, created_at)`, `show_media(page_id)`.

Scraped tables: **untouched.** No `sdk/` schema changes for the read-only phase.

### 8.1 Connection settings (H-3)
At client construction for `contributions.db`: `PRAGMA journal_mode=WAL;`
`PRAGMA busy_timeout=5000;` `PRAGMA synchronous=NORMAL;`. One writer / many
readers is the expected shape; WAL handles it. Write transactions are **small and
synchronous** — `{overlay/block upsert + revision insert}`, commit, done. No
transaction is held open across an editor session.

## 9. Nightly reconciler (the one new pipeline piece)

Runs after each read-model emit. Read-only against contributions except the
divergence/pointer columns:
- Re-resolve `show_pages.show_id` from `(corps_key, season)`; mark `status =
  'orphaned'` if the corps/season no longer exists (never delete).
- **Log loudly** if any `(corps_key, season)` maps to >1 scraped show (M-1 guard).
- For each override row in `state='edited'`, recompute the scraped row's
  `source_hash`; if changed, set `scrape_diverged = 1` (precise, per-row).
- Writes in **small batches** (e.g. 100 pages/tx) to avoid long write locks;
  runs off-peak when editing traffic is ~nil (H-3).
Idempotent; safe to re-run. Emits a short report (pages reconciled, rows diverged,
key collisions) like the existing scraper runbooks.

**Implemented:** `scripts/reconcile-contributions.ts` (`npm run reconcile:contributions`).
Dry-run by default; `--apply` persists orphan/divergence/show_id changes; `--limit N`
caps pages. Reads the scraped half exactly like the app's hybrid path —
the emitted read-model when `READ_MODEL_DB_URL` is set (production, post-emit), else
the relational DB (dev). It writes the contributions DB at `CONTRIBUTIONS_DB_URL`
(default `/data` in prod), so run it from a host with the repo + tsx that can reach
that DB. The collision (M-1) guard runs only against the relational table (the
read-model is keyed uniquely); a collision sets a non-zero exit code for alerting.
Note: it is **not** wired into `docker-entrypoint.sh` — the slim runtime image has no
tsx/source. Run it on a nightly cron from a box that has the repo (after the emit), or
point `CONTRIBUTIONS_DB_URL` at the production volume.

## 10. Media uploads & backup (R2)

- Reuse the existing R2 setup (read-model distribution) + `sharp` (already in
  `app/lib/media-cache.ts`). New **upload** server fn: validate type/size →
  `sharp.rotate()` (bake orientation) → re-encode to WebP **with metadata
  stripped** (no EXIF/GPS passthrough, L-1) → generate variants → `PutObject`
  under an `uploads/` prefix → insert `show_media`. Serve through the existing
  media proxy so dark-mode variants + caching come free. Drop zones POST here.
  Run sharp at **bounded concurrency** (4GB box).
- **Backup (DR):** `contributions.db` snapshotted/streamed from `/data` to a
  dedicated R2 prefix (e.g. `contributions-backup/`) on a schedule. Restore
  procedure documented in the runbook (M8). Distinct from the read-model bucket
  semantics — this prefix is write-once history, never swapped. R2 upload objects
  are write-once, so a DB restore to an older snapshot can at worst orphan newer
  media (harmless), never dangle (L-3).

## 11. Invariants

- **I-1** Scraped tables are never written by app code. (Only `sdk/` ingest writes them.)
- **I-2** A committed contribution survives every nightly emit unchanged.
- **I-3** `displayed = override ?? scraped`, evaluated per **row/value** at read time.
- **I-4** Pinned blocks cannot be deleted; one authored row per `(page_id,
  pinned_key)`, one override per `(page_id, pinned_key, natural_key)`.
- **I-5** `show_revisions` is append-only — no row is ever updated or deleted; a
  "revert" is a new forward revision restoring prior content.
- **I-6** Every write is `{overlay/block upsert + revision insert}` in one
  transaction.
- **I-7** Contributions live on the `/data` persistent volume (the durable store);
  R2 backup is DR. Writes **fail closed** if `/data` isn't a mount (§3.2).
- **I-8** Contributions anchor to `(corps_key, season)`, never to scraped `show_id`.
- **I-9** All writes require an authenticated session; `author_id` is always set.
- **I-10** The read path never requires a contributions row to exist — a page with
  no `show_pages` row renders fully from scrape + empty prompts (lazy create, M-4).
- **I-11** A scraped value the human overrode never reverts to scrape silently;
  only divergence is flagged.
- **I-12** Permission is decided server-side in one `authorize()` chokepoint
  (§6.5); UI gating is cosmetic. The client's validation is never trusted — every
  write re-parses its Effect Schema server-side (§6.6).
- **I-13** Editing is the default capability for any authenticated user; roles
  grant only extra (destructive/structural) powers, never basic edit access (§6.2).
- **I-14** Rich free-form content is stored/rendered as a structured node tree
  through a node-type allowlist, never as arbitrary HTML (§6.6).

## 12. Edge cases

- **Redeploy / container rebuild** → `contributions.db` is on `/data`, untouched
  by the deploy. Mount guard refuses writes if the volume is missing (I-7). ✔
- **Scraper re-keys a show** → `show_id` re-resolves; overrides stay put (anchored
  to corps+season + natural row key). ✔ via §5.
- **Scraper deletes/renames a corps or season** → `show_pages.status='orphaned'`;
  hide from nav, surface in an admin list. Never delete contributions.
- **Scraped row changes after a human overrode it** → that override row's
  `scrape_diverged=1`; precise banner; human chooses. Never auto-overwritten (I-11).
- **Scraper adds a brand-new repertoire row** after the page exists → it renders
  live immediately (no override = show scrape). Human improvements elsewhere
  unaffected. ✔ (this is the H-1 win).
- **Human hides a scraped row, scraper later removes it** → tombstone override is
  harmless/no-op; reconciler may prune dangling tombstones (deferred).
- **Two users edit the same row near-simultaneously** → last-write-wins on the
  override row; both writes in history; loser can revert. Optimistic-concurrency
  token (`updated_at` precondition) rejects a stale write with "refresh & retry".
- **First-ever edit on a show** → lazy-create `show_pages` row inside the first
  write transaction (M-4); read path already handled it without a row (I-10).
- **User edits but volume unmounted** → write fails closed with a clear message;
  nothing silently lost (I-7).
- **Empty section** → renders as an inviting prompt/drop zone, not blank/"N/A".
- **Malicious upload** (SVG/script, oversized, wrong type) → server-side type/size
  validation + sharp re-encode to WebP strips active content + metadata; reject
  non-image. Reuse existing SSRF host allowlist for embeds.
- **Untrusted embed URLs** (social) → allowlist platforms (IG/TikTok/YT/X); store
  URL, render via official embed or a safe link card, never raw iframe of arbitrary
  origin.
- **History sidebar diff fidelity (M-2)** → v1 renders a text diff of `plain` plus
  structured op summaries derived from `op`+before/after JSON ("added 2 images",
  "reordered blocks", "uniform primary #1a2b3c → #2f4f4f"). Full visual rich-diff
  is out of v1 scope, stated up front.
- **Edit on a locked page** → server fn rejects edits below `lock_level` with a
  clear message (§6.4); trusted+ pass. UI shows the lock state.
- **Stale client validation / client bypass** → server re-parses the Effect Schema
  (I-12); a forged payload that passed no client check still fails server-side.
- **User's role changes after they edited** → past revisions keep their frozen
  `actor_role` (§6.5); history meaning is stable.
- **Malicious rich content** (script in editor JSON) → node-type allowlist on the
  SSR renderer drops unknown nodes/attrs (I-14); structured tree, never raw HTML.
- **Self-warmed cache staleness (H-2)** → on any write, the server fn invalidates
  the page's cache key `(corps_key, season)` (and may re-warm) so the editor sees
  its own change immediately; scraped half keeps the 5-min TTL.
- **Revision history unbounded growth** → fine at this scale (text JSON); if it
  bloats, snapshot-compact old revisions (keep boundaries) — deferred, noted.
- **Spam / vandalism** → history + revert is v1 backstop; per-user rate limit;
  `role` field reserved for trusted/admin gating (M9).
- **Editor format migration** (swap Lexical→other) → `format` tag + `plain`
  fallback means old docs still render; lazy re-serialize on next edit.
- **Listen/announcement links rot** → store as data, optional periodic link-check
  (deferred); show "link may be dead" rather than 404-ing silently.

## 17. DCI Yearbooks — high-authority source ingestion

DCI publishes an official **Yearbook** PDF/flipbook each season (hosted on pubhtml5
under account `xada`, e.g. the 2017 book is `xada/nujr`, 148 pages). These are the
most authoritative source for a season's show data — full staff rosters by section,
design/arranging credits, repertoire, photos, and concept copy — and must seed the
show pages above any web scrape. Verified on the 2017 book, page 65 (Boston
Crusaders): a clean per-corps profile with Exec Director, Drum Majors, Brass,
Percussion, Color Guard, Visual + Additional Staff, naming composer/arranger/
electronics designers — exactly the seedable data the wiki wants.

### 17.1 Source shape (verified)
- Pages are **images** at `https://online.pubhtml5.com/xada/{bookId}/files/large/{n}.webp`
  (~400 KB, ~1366×1800, very legible). These hot-link fine with a browser UA (200);
  out-of-range pages 403.
- `…/javascript/config.js` carries `pageCount` (148 for 2017) + title, but the real
  `bookConfig` is an **encrypted blob** and `DownloadURL` is a placeholder
  (`["downloadURL"]`) — the actual PDF is resolved server-side.
- **Download/print is gated by an anti-bot slider captcha** (config has a `"slider"`
  field; the encrypted config deters scraping). **We do NOT automate the captcha** —
  defeating an anti-bot challenge is evasion and brittle/ToS-hostile.
- **Two acquisition paths, prefer the first:**
  1. **Human-supplied PDFs (preferred — CONFIRMED working).** PDFs committed under
     `data/yearbook/` (split into `.partNNN` over GitHub's 100 MB cap; reassembled
     by `scripts/reassembleYearbooks.mjs` in dev + Docker build). **Verified: the
     2013–2017 books carry embedded text (~105–135 of ~148 pages), extracted
     directly via `unpdf` — no OCR, no vision, no captcha.** See
     `sdk/src/yearbook/yearbookText.ts`. Status of the current set:
     2013/14/15/16/17 text-OK; 2017 is duplicated (remove one); the 2019 file is
     image-only (0 text pages) + oddly named (looks like a filtered export — re-grab
     a clean 2019); 2018 + 2020–2025 not yet supplied.
  2. **Image-only PDFs → local OCR (no vision-LLM needed).** For books with no text
     layer (e.g. the current 2019 file), render the page with poppler `pdftoppm` and
     OCR with `tesseract` on demand, per page (`sdk/src/yearbook/ocr.ts`). Verified
     against ground truth (2017 p65 OCR recovered all names; **cleaner** than the
     embedded text — OCR reads rendered glyphs so the letter-spacing artifacts
     disappear). Output feeds the *same* AI structured extraction as path 1. Host
     deps: poppler + tesseract + mupdf + ocrmypdf (installed). The un-gated
     `files/large/{n}.webp` images remain an option for years with no PDF at all.
- **Enumeration (open):** the `xada` homepage is JS-rendered (empty to curl), so the
  per-year `bookId`s need discovery — pubhtml5 bookcase API, a render pass, or a
  small hand-maintained `{season → bookId}` map (years are finite, ~2010–2025).
  Only needed for path 2. Tracked as OQ-8.

### 17.2 Authority model (the "high authority" requirement)
Yearbooks are a **machine source on the scraped side**, not human contributions —
but with the **highest authority among scraped sources**. Introduce a source-rank
on scraped show facts:

```
source_authority:  yearbook (100) > dcx-museum (60) > corps-site (40) > inferred (10)
```

- **Among scraped sources:** ingest/build prefers the highest-authority value, so a
  yearbook fact overrides a lower web-scraped one for the same field. Store
  `source` + `source_authority` on the show child rows (additive columns;
  `corps_show_designers`/`movements` already carry `source_url`).
- **Vs. human contributions:** the wiki principle still holds — a human override
  wins at render (I-3). But override of a yearbook-sourced row raises a **stronger,
  authority-aware divergence banner** ("differs from the official 2017 DCI
  Yearbook") instead of the generic one (§12). Humans can still correct a genuine
  yearbook typo; we just make disagreeing with the canon visible.
- **Provenance (resolves OQ-5 toward "show it"):** the read-only page shows a trust
  badge — "Source: 2017 DCI Yearbook" — on yearbook-seeded sections.

### 17.3 Ingestion pipeline (new milestone M10)
1. **Acquire** the book (§17.1): prefer a human-supplied `sdk/yearbooks/{season}.pdf`;
   else enumerate `{season → bookId, pageCount}` (OQ-8) and fetch page images
   politely (bounded concurrency, cache to `media-cache.db`/R2; never hammer pubhtml5).
2. **Normalize to pages.** Embedded text → `unpdf` (`yearbookText.ts`). No text layer
   → per-page OCR via poppler `pdftoppm` + `tesseract` (`ocr.ts`), or whole-book
   `ocrmypdf` to bake a text layer. Either way the downstream step gets plain text.
3. **Vision/text-extract** per page → strict JSON via the existing AI-extract pattern
   (`sdk/src/staffAiExtract.ts`: `claude -p` with `codex` fallback — both present).
   Schema-validate with Effect Schema. Confidence tagged; LOW pages queued for review
   like staff. (Embedded PDF text, when present, can skip vision entirely.)
4. **Map** each page to `(corps_key, season)` — page headers carry the corps name +
   site (e.g. "bostoncrusaders.org / Boston, MA"); reuse the corps alias/slug
   resolver. Pages without a corps (intros, ads, recaps) are skipped/classified.
5. **Ingest** into the relational show tables with `source='yearbook'`,
   `source_authority=100`, and the source page URL for citation. Re-runnable/idempotent
   per `(season, page)`; never clobbers a human contribution (I-1/I-2 unaffected —
   this writes scraped tables only).
6. Flows to the app automatically via the existing `rm_show_detail` emit (M1a).

### 17.4 Invariants / notes
- **I-15** Yearbook ingestion writes only scraped tables (never `contributions.db`),
  so it composes with the overlay model unchanged.
- Cost/scale: ~150 pages × ~15 seasons ≈ 2.2k vision calls — a bounded one-time
  backfill + a yearly increment, run offline like the other scrapers (not on the
  request path). Bound concurrency on the 4 GB box; cache aggressively.
- Legal/etiquette: hot-linking DCI's own published assets for a DCI fan reference;
  fetch politely, attribute clearly, cache rather than re-pull.

## 18. Citations & references

Goal: every authored claim can be backed by a source, and readers see numbered
references (Wikipedia-style) so the wiki is *credible*, not just editable. Citations
also unify with the provenance/authority model (§4, §17): a scraped/yearbook
`source_url` is just a high-authority citation.

### 18.1 Principles (the "think hard" part)
- **Citations are first-class, page-scoped, deduplicated entities** — a bibliography.
  Content *references* a citation by stable `citation_id`; cite a source once,
  reference it from many places. This is Wikipedia's model and the reason numbering
  can be **derived at render** (order of first appearance → [1..n]) and stay stable
  across edits. Never store the number.
- **Two reference modes, one citation store:**
  - *Block/row-level* — a structured block (uniform, props, a repertoire override
    row, …) cites `citationIds: string[]`. Stored in the block's `content_json`; no
    new linking table.
  - *Inline* (free-form, rides with M4) — the Lexical doc embeds a `citation` inline
    node carrying `citation_id`, rendered as a superscript `[n]`.
- **Provenance = citation.** Yearbook/scraped rows already carry `source_url` +
  `source_authority` (§17.2). Those surface in the same References list, sorted to
  the top by authority, badged "DCI 2017 Yearbook". So "official source" and
  "fan-added citation" are one concept with a rank, not two systems.
- **Low-friction capture (the UX win):** paste a URL → the server best-effort
  fetches Open-Graph `title`/`site_name`/`publisher` to prefill the citation (reuse
  the existing fetch/metadata path; same SSRF host posture). The contributor can
  edit. Dedupe by normalized URL so the same source isn't added twice.
- **Trust signals:** a citation `type` (official-announcement / interview / article /
  social / video / yearbook / program / other) drives a small icon + sort order.
  Optional `[citation needed]` marker on unsourced authored claims (deferred).

### 18.2 Data model (contributions.db)
```sql
show_citations (
  citation_id    TEXT PRIMARY KEY,
  page_id        TEXT NOT NULL,
  url            TEXT,                 -- null for offline sources (book, program, interview)
  normalized_url TEXT,                 -- dedupe key (strip protocol/www/utm/hash)
  title          TEXT,
  publisher      TEXT,
  type           TEXT NOT NULL DEFAULT 'other',
  quote          TEXT,                 -- optional supporting excerpt
  accessed_at    TEXT,
  created_at     TEXT NOT NULL,
  created_by     TEXT NOT NULL,
  UNIQUE (page_id, normalized_url)     -- one citation per source per page
)
```
- References live in `content_json` (`citationIds: string[]`) for blocks/overrides
  and in the editor doc for inline — no separate join table.
- Numbering is render-derived; the References section walks the page in document
  order, assigns [1..n] on first appearance, lists them with backlinks (↑) to the
  citing sections.
- Citations are versioned: create/edit is a normal write recorded in
  `show_revisions` with `target_kind='citation'` (append-only history applies).

### 18.3 UX flow
- **Edit mode:** each section has a subtle **"Sources"** affordance → a `+ cite`
  picker: paste a URL (auto-title), pick an existing page citation, or add an
  offline source (type + free description). Selected sources show as removable chips.
- **Read mode:** a small `Sources: [1][2]` line under each section; a page-bottom
  **References** list (numbered, type icon, title → link, accessed date, backlinks).
  Clicking `[n]` scrolls to the reference.
- **Free-form (M4):** a toolbar "cite" inserts an inline `[n]` bound to a citation.
- **Provenance:** yearbook/scraped `source_url`s auto-appear in References (read-only,
  authority-sorted to the top), so high-authority sources lead.

### 18.4 Milestone M11 (citations)
- **M11a** — `show_citations` table + citation server-fns (`createCitation` with
  OG-metadata prefetch + dedupe, `listCitations`, attach via block `citationIds`) +
  the per-section Sources line + the page References section. (structured blocks)
- **M11b** — inline citations in the free-form Lexical editor (custom node). Rides M4.
  **Still deferred:** a custom Lexical inline node + insert toolbar + render/numbering
  is a self-contained editor feature (see OQ-9 on granularity). The read-side
  allowlist (lexical-render.tsx) must gain a `citation` case when this lands.
- **M11c — DONE.** Scraped/yearbook `source_url`s surface as read-only, authority-
  sorted references via `collectScrapedReferences(show)` →
  `<ReferencesSection provenance>` (yearbook sources badged "Official", sorted to
  the top). Unifies provenance with the citation bibliography per §18.1.

### 18.5 Invariants / edge cases
- **I-16** A citation is page-scoped + deduped by `normalized_url`; reference
  numbering is render-derived (never stored), so references stay stable across edits.
- Dead links → periodic link-check (deferred); show "link may be dead", don't hide.
- Deleting a still-referenced citation → warn; keep the citation but mark orphaned
  rather than break `[n]` anchors.
- Offline sources (book/program/personal communication) → `url` null, rendered from
  `title`/`publisher`/`type`, no link.
